# 2100年の日本（town-2100）

[English](README.en.md)

2100年までの日本の人口を、地図で見るアプリです。日本、都道府県、町の順に絞り込み、町ごとの人口と年齢の構成、その人口が施設ごとの「人口の目安」を上回るか下回るかを見られます。人口を地域のあいだで割り振り直すと何が変わるかも見られ、AIには、このアプリの計算を道具として呼ばせ、その結果をもとに答えさせます（この版では、AIへの質問は動きません）。

このアプリは、何を残し、何を残さないかを勧めません。決めるための事実を見せるだけで、決めるのは使う人です。

作者の見解：全国の地方が同時に創生すると、人口の面では成り立たない、と作者は考えています。このアプリはその見解の証明ではなく、確かめるための材料を並べたものです。

## 3分で触る（審査員の方へ）

公開ページが無い間は、手元で動かせます（[動かす・試す・作る](#動かす試す作る)。`npm ci` のあと `npm run dev`）。

1. **日本の地図**：開くと2050年（社人研の公式推計の最後の年）が出ます。都道府県ごとに色が付きます。色は2020年に対する増減で、減るほど赤茶、増えると青です。2100年まで見るには、下の年のスライダーの再生ボタン（▶）を押すか、スライダーを動かします。2020年から2100年まで、5年刻みです。
2. **県から町へ**：県を押すと、その県の市区町村の地図に変わります。町の名前の検索もできます。政令指定都市と東京23区は、区ごとに表示します。
3. **町の詳細**：町を押すと、人口の推移（公式の推計は実線、このアプリの試算は破線）、5歳ごと・男女別の人口ピラミッド、65歳以上と0〜14歳の割合、施設ごとの「人口の目安」との比較が出ます。施設は48種類で、このアプリが必須として扱う8種類（飲食料品小売業、郵便局、銀行（中央銀行を除く）、一般診療所、介護老人福祉施設、一般病院、通所・短期入所介護事業、訪問介護事業）を先に、残りは折りたたんで出します。画面に出る施設の名前は `public/data/facilities.json` の名前と同じです（AIの文章は Claude が書くので、言い方が違うことがあります）。町の人口を各施設の目安に当てはめた結果は、「人口の目安を上回る」「境目」「人口の目安を下回る」の3つで出ます。
4. **前提を変える**：2050年より後の計算に使う前提を動かします。子どもの生まれやすさ（2050年の水準の0.6〜1.4倍）、人口の移動（2050年ごろの傾向を続ける、または2100年に向けて少しずつ止まる。強さは0〜1.5倍）、インフラ連動の過疎の加速（なし・弱い・強い）。地図と数字がその場で変わります。2050年までの数字は、どう動かしても変わりません。
5. **人口の割り振り**：全国の人口を変えずに、ある県や町の人口を増やす（または減らす）と、ほかの地域がどう変わるかを計算します。試し方：(1) 年のスライダーを2100年に合わせる。(2) 「人口の割り振り」の「人口を増減させる地域」で和歌山県を選ぶ（何も選んでいない時は、はじめから和歌山県です。増やす割合の初期値は10%）。(3) 「地図に反映する」を押す。地図の色が、割り振りによる人口の変化に変わります。和歌山県の人口が10%（約2.6万人）増えると、ほかの地域が合わせて同じ人数だけ減ります。そのとき高野町は470.6人から517.7人になり、人口500人という目安を下回らなくなります。500人を目安とする施設は8つです（「飲食料品小売業」「飲食店」「酒場、ビアホール」「旅館、ホテル」「郵便局」「一般診療所」「歯科診療所」「介護老人福祉施設」）。この500人は、元の表で「0〜1,000人」の区間の中央の値を使ったもので、実際に観測された境目ではありません。人口の差は全国で見ると小さいので、施設ごとに、人口の目安を下回らなくなる町と、下回る町の数がどう変わるかで見せています（この例では、48施設のうち12施設の町の数が変わります）。表の施設名を押すと、その施設で目安をまたいだ町が、県の地図では輪（青の実線が「人口の目安を下回らなくなる町」、赤茶の破線が「人口の目安を下回る町」）、全国の地図では県ごとの印（「+n −n」）で示されます。割り振りを消すには、割り振りが地図にある間に出る「割り振りを地図から消す」を押すか、Esc キーを押します。
6. **AIに質問**：**この版では、AIへの質問は動きません。** 画面には「AIに質問」の入力欄と質問の例のボタン（5つ）がありますが、押しても答えは出ず、「このバージョンでは、AIへの質問は使えません（AIの接続先がまだ用意されていません）。地図、数値、前提の調整、人口の割り振りはそのまま使えます。」と出ます。この文は、AIの接続先（Worker）が見つからないとき（404・405、または Worker の答えではない本文）に出ます。接続先が一度答えたあとで接続が切れたとき、または接続先が「いまは使えない」と返したときは、代わりに「いまはAIに接続できません。時間をおいて、もう一度お試しください。」と出ます。質問の例の保存済みの答えは、まだ1件も作っていません（`public/data/cached_answers.json` の5件は、どれも `pending` で、作る前の答えは画面に出しません）。そのため「保存済みの質問」のボタンも、いまは出ません。

   以下は、Worker を公開したあとの作りです（この版では動きません）。日本語で質問すると、Claude が計算の道具を呼び、その結果から答えます。答えの下の「使った道具と数字」を開くと、どの道具に何を渡し、何が返ったかを確かめられます。質問の例の保存済みの答え（Worker なしで即座に出るもの）は、Claude に答えさせ、作者が確認してから `public/data/cached_answers.json` に保存し、確認済みのものだけを画面に出します。自由入力は、Worker を通して Claude を呼びます。回数に上限があり（既定は、1つのIPで1日60回、全体で1日400回。上流への呼び出しの回数で、1つの質問が最大9回の呼び出しになりうるので、60回は質問60個とは限りません。ほかに、1つのIPで60秒に20回まで）、上限に達すると、確認済みの保存済みの答えがあればそれを出します。質問は200文字までです。

見分け方の約束：2050年より後の数字には、必ず「試算」の印が付き、グラフでは破線になります。「予測」とは書きません。2050年までは「公式推計」、2020年は「実績（国勢調査）」と出ます。割り振りを地図に出している間、2050年までの年で割り振りによって変わった数字は、公式の値ではなくこのアプリの計算なので、見出しに「公式推計」の代わりに「割り振り後」の印と「公式推計をもとにこのアプリが計算」という注記が付きます。AIの答えのカードも同じで、2050年より後の年を示す答え（見分けがつかないときは、示すものとして扱います）には、「試算」の印と「2050年より後は、このアプリの試算です（予測ではありません）」の注記を付けます。

地図はキーボードでも使えます。Tab で地図に入ると、止まる場所は地図ごとに1つです（地図の手前に「地図をとばして、年の選択へ」というリンクが出ます）。矢印キーで、その向きの隣の地域へ、PageUp と PageDown で前と次の地域へ、Home と End で最初と最後の地域へ移り、Enter か Space で選びます。PageUp・PageDown を使えば、矢印では届かない地域も含めて、すべての地域に着けます（全国の地図と47の県の地図で、テストが確かめています）。

## 数字の出どころと確かめ方

**人口の土台**は、国立社会保障・人口問題研究所（社人研）の「日本の地域別将来推計人口（令和5年推計）」です。2020年の国勢調査を基準に、市区町村ごとに2050年までの人口が公表されていて、計算に使った前提（生残率、純移動率、子ども女性比、0〜4歳の性比）も市区町村ごとに公表されています。2050年より先の、市区町村ごとの公式の推計はありません。

**このアプリの計算**は、その前提を使って自分で計算し直すエンジン（コーホート要因法。5歳ごと・男女別・5年刻み）です。まず、公表されている前提から2050年の公式の結果を再現できることを確かめました（前提が公表されている1,871地域）。

| 年 | 地域ごとの人口のずれ：中央値 | 90%の地域が収まる幅 | 最大 |
|---|---|---|---|
| 2025年 | 0.0039% | 0.042%以内 | 0.705% |
| 2030年 | 0.0041% | 0.051%以内 | 0.995% |
| 2040年 | 0.0049% | 0.057%以内 | 0.841% |
| 2050年 | 0.0053% | 0.076%以内 | 1.39% |

2050年は、99.47%の地域が0.5%以内に収まります。全国の合計は、このアプリが104,686,401人、公式が104,686,386人（1,884地域の合計。前提が公表されていない13村は、公式の年齢別人口をそのまま使っています）。この結果は、テストが毎回確かめます（2050年の中央値が0.01%以内、98%以上の地域が0.5%以内、最大が2%以内でなければ失敗します）。数字を確かめた経緯は [docs/dev-log.md](docs/dev-log.md) にあります。

このアプリの2050年までの数字は、社人研が発表した値と、町では数人（テストが全1,884地域で確かめた最大は10人未満）、都道府県では数十人（100人未満）ほど違うことがあります。たとえば田辺市の2050年は、社人研の表では42,309人、このアプリの計算では42,311人です。町の詳細の「人口の推移の数字を表で見る」を開くと、表の下に同じ注記が出ます。

**2050年より後**は、既定では、2045→2050年の期の前提を据え置いて延ばします。全国の2100年は 63,279,524人（6,328万人）で、社人研が別に公表している長期の参考推計（2071〜2120年。出生中位・死亡中位で2100年は6,278万人）と近い値です。前提は画面で変えられます。

| 2100年の全国の人口 | このアプリの試算 |
|---|---|
| 前提を据え置く（既定） | 6,328万人 |
| 人口の移動が2100年に向けて止まる | 5,852万人 |
| 子どもの生まれやすさ 1.2倍 | 7,093万人 |
| 子どもの生まれやすさ 0.8倍 | 5,634万人 |
| 移動が止まり、1.2倍 | 6,506万人 |

人口の移動が止まると、全国の合計は減りますが、人口が減りつつある小さな町では、転出も止まるので、かえって多くなることがあります（田辺市は2100年に1.19万人が1.37万人）。

**インフラ連動の過疎の加速**は、このアプリが加えた仮定です。公式の前提は、病院や店の有無と転出を結び付けていません。この仮定は「必須の施設が人口の目安を下回ると、その町から出る人が増える」と置いた計算で、どれだけ増えるかを測った根拠はありません。幅を見るための仮定で、初期はオフです。

**施設の「人口の目安」**は、国土交通省国土政策局の表「サービス施設の立地する確率が50%及び80%となる自治体の人口規模（三大都市圏を除く）」です。ある人口規模の自治体のうち、その施設が1つでもある自治体の割合が50%（p50）・80%（p80）になる人口規模です。2009〜2012年の統計で、三大都市圏（埼玉・千葉・東京・神奈川・岐阜・愛知・三重・京都・大阪・兵庫・奈良の11都府県）を除いて集計されています。画面では、町の人口を施設ごとに、50%の人口規模を下回る「人口の目安を下回る」、50%以上80%未満の「境目」、80%以上の「人口の目安を上回る」のどれかで出します（50%と80%の値が同じ施設に「境目」はありません）。これは目安であって、施設の閉鎖の予告ではありません。三大都市圏の町には表の対象外と注記して、参考として出します。

### 数字の限界

- 2050年より後は、予測ではなく、前提を置いた計算です。小さな町ほど、前提の影響が大きく出ます。
- 施設の目安は、2009〜2012年の統計です。人口が同じでも、いまの施設の有無とは一致しません。
- 前提が公表されていない13の村（檜枝岐村、利島村、御蔵島村、青ヶ島村、粟島浦村、平谷村、野迫川村、下北山村、上北山村、北山村、三島村、座間味村、渡名喜村）は、2050年まで公式の値を使い、それ以降は同じ県の変化率で延ばします。この村に印を付ける表示は、この版の画面にはまだありません。
- 基準は2020年の国勢調査と、2020年ごろの市区町村の区域です。合併などで境界が変わっても反映しません。
- 地図の境界は、表示用に簡略化した粗い図形です（測量・面積・行政区域の確認には使えません）。海岸線と行政界は、数十〜数百m以上ずれる所があります。0.01平方キロメートル未満の小さな岩礁はほとんど描かれません。
- 北方領土の6村（色丹村、泊村、留夜別村、留別村、紗那村、蘂取村）は描いていません。社人研にその数字が無いためで、領土についての見解を示すものではありません。歯舞群島は国土数値情報で根室市に含まれているので、根室市の図形に入っています。

## Claude をどう使ったか

**開発で**：このリポジトリのコードは、すべて Claude Code（コマンドラインの Claude）で、このハッカソンの期間中（2026年11月5日〜6日）に書きました。データ、計算エンジン、地図と画面、AIと中継の流れを、別々の git worktree（書き込む場所を分けた作業用の複製）で並列に進め、タスクごとに、実装した Claude とは別の Claude が独立にレビューしました。判断・指摘・修正の記録は「台帳」に残してありますが、台帳、タスクの指示書と報告書、設計書、実装計画、画面のスクリーンショットは、このリポジトリには入れていません（ここからは読めません）。以下の数字は、コミット fa21f09 の時点で、台帳・報告書・git から数え直したものです。

- 実装のタスク：17（データ作り、計算エンジン、施設の表、境界の図形、中継、AIの道具、画面の骨組みと地図、町の詳細、前提と割り振りの画面、AIの画面、割り振りの地図表示、文書）
- タスクごとの独立レビュー（Claude Sonnet 5.5。台帳の方針による記録で、1件ごとのモデルは残していません）：17タスクすべてをレビュー。1回目で承認されたのは7タスク、残り10タスクは指摘を受けて1回ずつ直し、直した後にもう一度レビューして承認されました（修正ラウンド10、再レビュー10回）
- その指摘の内訳：致命的 0件、重要 26件（例：中継が、画面から来た項目の一部をそのまま通していた／回数の上限が同時アクセスで外れた／ファイルの読み込みが止まるとAIの画面が固まった／失敗できないテスト。詳しくは [docs/dev-log.md](docs/dev-log.md)）
- 最後の全体レビュー（2026年11月5日。Claude Opus 5.5 の2人。A：安全性・公開・文書の正直さ、B：実際の使い方・使いやすさ）：Aは致命的 1件（この README が以前の状態を書いていた。この更新で直しました）と重要 5件（中継が実際の API に受け入れられない恐れのある点など）、Bは致命的 0件・重要 5件（動かないAIを動くように案内していた画面、地図の全地域が Tab の停止位置になっていた点など）
- 修正の波（2026年11月6日）：その指摘を、4つの流れ（中継／AIと割り振りの画面／地図・骨組み・フッター／データ作りの安全装置と無視設定）で直しました。流れごとに、実装者（Claude Sonnet 5.5）、タスクのレビュー（中継だけ Claude Opus 5.5。ほかは Claude Sonnet 5.5）、直した後の再レビューがあり、合わせて7回のレビューで重要 8件（致命的 0件）が見つかりました。データ作りの流れは、レビュー1回と修正1回で、再レビューはしていません。ほかの流れも、最後の修正ラウンドは再レビューをせず、作者側の取りまとめ役（進行役）のセッションが本番コードの差分を読んで確かめました
- レビューは、変異テスト（コードをわざと壊して、テストが失敗するかを調べる）でも確かめました
- Claude Code の自動のセキュリティ点検も、作業の途中で3回コメントしました（中継が画面から道具の定義を受け取っていること、データ取得のファイル名の確認、1日の回数の書き込み失敗の扱い）。1回目と3回目は中継の作りを変え（道具の定義を中継の側に置く、1日の合計を16個のキーに分ける）、2回目は取得のファイル名を確かめる検査を足しました
- **別の会社の AI によるレビューは、1回も行っていません。** 他社のレビューの道具が、使えませんでした（Codex は利用枠の上限、Antigravity は権限の設定で止まりました）。レビューはすべて Claude です

**製品の中で**（この版では、Worker を公開していないため動きません。作りと、テストで確かめた範囲を書きます）：「AIに質問」は、Anthropic の API（モデル `claude-sonnet-5-5`）を、小さな Cloudflare Worker 経由で呼びます。API キーは Worker にだけ置き、画面側（ブラウザ）には出しません。

- Claude は、次の8つの計算の道具を呼んで答えます。道具の名前・説明・入力の形は、Worker の側で決めたものだけが使われ、画面から送られた値は使いません。
  1. `find_area`：地域の名前からコードを探す
  2. `get_series`：地域の人口の推移（65歳以上の人数と割合も）
  3. `compare_sources`：公式の推計とこのアプリの試算を比べる
  4. `run_projection`：前提を変えて計算し直す
  5. `facility_check`：町の人口を施設の目安に当てはめる
  6. `run_allocation`：人口の割り振りを計算する
  7. `find_similar_now`：2100年の人口が、いまの人口と近い町を探す
  8. `count_areas`：条件に合う地域の数を数える
- 道具は、ブラウザの中で動く同じ計算エンジンを呼びます。Claude は結果を日本語で説明します。
- **答えの中の数字が、計算の結果に出てくる数字かどうかを確かめます**（小さな誤差は許します。最後に書いた桁の半分と、値の0.5%のうち、大きいほう）。確かめるのは、その質問で道具が返した結果のどこかに、同じ数字があるかどうかだけです。町や年が合っているか、説明が正しいかまでは確かめません。見つからない数字があると、道具の結果にある数字だけで言い直すよう、1回だけ頼みます。それでも確かめられない数字が残った答えは、画面に「次の数字は、計算の結果で確かめられませんでした」という警告をつけて表示します。自分で計算した合計や比（たとえば「約28%」）は、道具の結果に無いので、警告されます。次のものは検査しません：行頭の番号（「1.」「（3）」など）、アルファベットに続く数字（「p50」など）、「第」が前に付く数字、年・歳・代・位・番・月・日・章・節・号・条が後ろに付く整数（「2050年」「65歳以上」「11月5日」など）、人・世帯・戸・円・件・軒・台が付かない1900〜2100の4桁の整数（年）、道具の結果に出てくる地域コードと同じ2桁・5桁の整数（同じ単位が付かないもの）、単位・%・倍・割・小数点・桁区切りの付かない0〜10の整数、「2026/11/05」のような日付。漢数字（「三万人」など）は読みません。
- 人が確かめる手段として、答えの下に「使った道具と数字」を開けます。割り振りの質問では、地図も同じ状態に動かせます。
- モデルの出力は、HTML として解釈せず、文字としてだけ表示します。
- Worker の守り：画面から来た `messages` は決まった項目から作り直し、上流への要求は定数と、作り直した `messages` と、道具の定義だけで作り、リダイレクトは追わず、すべての応答に `nosniff` を付け、想定外の失敗は同じ形の 500 にします。ログに出すのは固定の文字列だけです（Workers Logs。接続元の IP や API キーは出しません）。1日の回数の数え上げは、書き込みの失敗では要求を通し、読み出しの失敗では止めます。詳しくは [worker/README.md](worker/README.md) です。
- AIには、勧めない・予測と書かない・「残せない」と書かない、といった決まりを、Worker の側の指示で渡しています。

## 動かす・試す・作る

必要なもの：Node.js と npm（開発は Node 26 で行いました）。データを作り直す場合は Python 3（標準ライブラリだけ。開発は 3.14）。

```sh
npm ci              # 依存関係を入れる
npm run dev         # 開発用サーバー（http://localhost:5173）
npm test            # テスト（Vitest）
npm run typecheck   # 型の検査（画面側と Worker 側）
npm run build       # 公開用のファイルを dist/ に作る（ソースマップは作らない）
npm run test:py     # データ作りのテスト（python3 -m unittest と同じ。先に python3 -m pipeline.fetch_sources が必要）
```

`build` ブランチのコミット fa21f09（2026-11-06）で確かめた結果です。

- `npm test`：50ファイル1241件がすべて通る
- `npm run typecheck`（画面側と Worker 側）と `npm run build`：エラーも警告もなし。`dist/` にソースマップ（`.map`）はできない
- `python3 -m unittest`：`data/raw`（`python3 -m pipeline.fetch_sources` で取得）がある時は122件がすべて通る。無い時は101件が動き、データを要する4つのテストの塊が「ファイルが無い」というエラーで止まる

データの作り直し（`public/data` には作った結果を入れてあるので、普段は要りません）：

```sh
python3 -m pipeline.fetch_sources     # 社人研の Excel を data/raw に取得し、SHA256 を照合
python3 -m pipeline.build_areas       # 地域ごとの人口と前提の JSON（public/data/areas、groups.json、index.json）
python3 -m pipeline.build_facilities  # 施設の人口の目安（public/data/facilities.json）
bash pipeline/build_geometry.sh       # 境界の TopoJSON（public/data/geo）。国土数値情報の zip を取得して簡略化
python3 -m pipeline.check_codes       # 社人研の地域と境界のコードの突き合わせ
```

AI の中継（Worker）：作りと設定は [worker/README.md](worker/README.md)、画面から Worker への接続は [docs/ai-endpoint.md](docs/ai-endpoint.md)。Worker の公開には、Anthropic の API キーと、そのワークスペースの利用上限の設定、Cloudflare の Workers 有料プラン（Paid）、KV の作成が要り、これらは作者が行います（キーはコードにも設定ファイルにも書きません）。この版には公開した Worker はありません。
