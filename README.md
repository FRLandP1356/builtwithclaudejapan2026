# 2100年の日本（town-2100）

[English](README.en.md)

2100年までの日本の人口を、地図で見るアプリです。日本、都道府県、町の順に絞り込み、町ごとの人口と年齢の構成、その人口でどんな施設が成り立ちうるかを見られます。人口を地域のあいだで割り振り直すと何が変わるかも見られ、AIには、計算した結果だけにもとづいて答えさせます。

このアプリは、何を残し、何を残さないかを勧めません。決めるための事実を見せるだけで、決めるのは使う人です。

作者の見解：全国の地方が同時に創生すると、人口の面では成り立たない、と作者は考えています。このアプリはその見解の証明ではなく、確かめるための材料を並べたものです。

## 3分で触る（審査員の方へ）

公開ページが無い間は、手元で動かせます（[動かす・試す・作る](#動かす試す作る)。`npm ci` のあと `npm run dev`）。

1. **日本の地図**：都道府県ごとに色が付きます。色は2020年に対する増減で、減るほど赤茶、増えると青です。下の年のスライダーで、2020年から2100年まで、5年刻みで動かせます。
2. **県から町へ**：県を押すと、その県の市区町村の地図に変わります。町の名前の検索もできます。政令指定都市と東京23区は、区ごとに表示します。
3. **町の詳細**：町を押すと、人口の推移（公式の推計は実線、このアプリの試算は破線）、5歳ごと・男女別の人口ピラミッド、65歳以上と0〜14歳の割合、施設ごとの「人口の目安」との比較が出ます。施設は48種類で、このアプリが必須として扱う8種類（診療所、郵便局、飲食料品店、一般病院、銀行、介護老人福祉施設、通所・短期入所介護、訪問介護）を先に、残りは折りたたんで出します。
4. **前提を変える**：2050年より後の計算に使う前提を動かします。子どもの生まれやすさ（2050年の水準の0.6〜1.4倍）、人口の移動（2050年ごろの傾向を続ける、または2100年に向けて少しずつ止まる。強さは0〜1.5倍）、インフラ連動の過疎の加速（なし・弱い・強い）。地図と数字がその場で変わります。2050年までの数字は、どう動かしても変わりません。
5. **人口の割り振り**：全国の人口を変えずに、ある県や町の人口を増やす（または減らす）と、ほかの地域がどう変わるかを計算します。例として、2100年に和歌山県の人口を10%（約2.6万人）増やすと、ほかの地域が合わせて同じ人数だけ減ります。そのとき高野町は470.6人から517.7人になり、人口500人が目安の8つの施設（飲食料品小売業、飲食店、酒場・ビアホール、旅館・ホテル、郵便局、一般診療所、歯科診療所、介護老人福祉施設）の目安を超えます。人口の差は全国で見ると小さいので、施設ごとに「目安を超える町の数」がどう変わるかで見せています（この例では、48施設のうち12施設の町の数が変わります）。
6. **AIに質問**：日本語で質問します。Claude が計算の道具を呼び、その結果から答えます。答えの下の「使った道具と数字」を開くと、どの道具に何を渡し、何が返ったかを確かめられます。質問の例は5つあります。自由入力は、Worker を通して Claude を呼びます。1人あたり1日の回数に上限があり（既定は1つのIPで1日20回、全体で1日300回。1つの質問が最大9回の呼び出しになりうるので、20回は質問20個とは限りません）、上限に達すると、保存済みの答えがあればそれを出します。質問は200文字までです。**保存済みの答え（Worker なしで即座に出る5件）は、このコミットの時点ではまだ作っていません**（`public/data/cached_answers.json` の状態が `pending`。作る前の答えは出さない作りです）。実際の Claude の答えを人が確認して保存してから、この文を直します。

見分け方の約束：2050年より後の数字には、必ず「試算」の印が付き、グラフでは破線になります。「予測」とは書きません。2050年までは「公式推計」、2020年は「実績（国勢調査）」と出ます。

## 数字の出どころと確かめ方

**人口の土台**は、国立社会保障・人口問題研究所（社人研）の「日本の地域別将来推計人口（令和5年推計）」です。2020年の国勢調査を基準に、市区町村ごとに2050年までの人口が公表されていて、計算に使った前提（生残率、純移動率、子ども女性比、0〜4歳の性比）も市区町村ごとに公表されています。2050年より先の、市区町村ごとの公式の推計はありません。

**このアプリの計算**は、その前提を使って自分で計算し直すエンジン（コーホート要因法。5歳ごと・男女別・5年刻み）です。まず、公表されている前提から2050年の公式の結果を再現できることを確かめました（前提が公表されている1,871地域）。

| 年 | 地域ごとの人口のずれ：中央値 | 90%の地域が収まる幅 | 最大 |
|---|---|---|---|
| 2025年 | 0.0039% | 0.042%以内 | 0.705% |
| 2030年 | 0.0041% | 0.051%以内 | 0.995% |
| 2040年 | 0.0049% | 0.057%以内 | 0.841% |
| 2050年 | 0.0053% | 0.076%以内 | 1.39% |

2050年は、99.47%の地域が0.5%以内に収まります。全国の合計は、このアプリが104,686,401人、公式が104,686,386人（1,884地域の合計。前提が公表されていない13村は、公式の年齢別人口をそのまま使っています）。この結果は、テストが毎回確かめます（2050年の中央値が0.01%以内、98%以上の地域が0.5%以内、最大が2%以内でなければ失敗します）。数字を確かめた経緯は [docs/dev-log.md](docs/dev-log.md) にあります。

**2050年より後**は、既定では、2045→2050年の期の前提を据え置いて延ばします。全国の2100年は 63,279,524人（6,328万人）で、社人研が別に公表している長期の参考推計（2071〜2120年。出生中位・死亡中位で2100年は6,278万人）と近い値です。前提は画面で変えられます。

| 2100年の全国の人口 | このアプリの試算 |
|---|---|
| 前提を据え置く（既定） | 6,328万人 |
| 人口の移動が2100年に向けて止まる | 5,852万人 |
| 子どもの生まれやすさ 1.2倍 | 7,093万人 |
| 子どもの生まれやすさ 0.8倍 | 5,634万人 |
| 移動が止まり、1.2倍 | 6,506万人 |

人口の移動が止まると、全国の合計は減りますが、人口が減りつつある小さな町では、転出も止まるので、かえって多くなることがあります（田辺市は2100年に1.19万人が1.37万人）。

**インフラ連動の過疎の加速**は、このアプリが加えた仮定です。公式の前提は、病院や店の有無と転出を結び付けていません。この仮定は「必須の施設が人口の目安を下回ると、その町から出る人が増える」と置いた計算で、どれだけ増えるかを測った根拠はありません。幅を見るための仮定で、初期はオフです。

**施設の「人口の目安」**は、国土交通省国土政策局の表「サービス施設の立地する確率が50%及び80%となる自治体の人口規模（三大都市圏を除く）」です。ある人口規模の自治体のうち、その施設が1つでもある自治体の割合が50%（p50）・80%（p80）になる人口規模です。2009〜2012年の統計で、三大都市圏（埼玉・千葉・東京・神奈川・岐阜・愛知・三重・京都・大阪・兵庫・奈良の11都府県）を除いて集計されています。画面では、人口が目安を上回る、境目、目安を下回る、のどれかを出します。これは目安であって、施設の閉鎖の予告ではありません。三大都市圏の町には表の対象外と注記して、参考として出します。

### 数字の限界

- 2050年より後は、予測ではなく、前提を置いた計算です。小さな町ほど、前提の影響が大きく出ます。
- 施設の目安は、2009〜2012年の統計です。人口が同じでも、いまの施設の有無とは一致しません。
- 前提が公表されていない13の村（檜枝岐村、利島村、御蔵島村、青ヶ島村、粟島浦村、平谷村、野迫川村、下北山村、上北山村、北山村、三島村、座間味村、渡名喜村）は、2050年まで公式の値を使い、それ以降は同じ県の変化率で延ばします。この村に印を付ける表示は、この版の画面にはまだありません。
- 基準は2020年の国勢調査と、2020年ごろの市区町村の区域です。合併などで境界が変わっても反映しません。
- 地図の境界は、表示用に簡略化した粗い図形です（測量・面積・行政区域の確認には使えません）。海岸線と行政界は、数十〜数百m以上ずれる所があります。0.01平方キロメートル未満の小さな岩礁はほとんど描かれません。
- 北方領土の6村（色丹村、泊村、留夜別村、留別村、紗那村、蘂取村）は描いていません。社人研にその数字が無いためで、領土についての見解を示すものではありません。歯舞群島は国土数値情報で根室市に含まれているので、根室市の図形に入っています。

## Claude をどう使ったか

**開発で**：このリポジトリのコードは、すべて Claude Code（コマンドラインの Claude）で、このハッカソンの期間中に書きました。データ、計算エンジン、地図と画面、AIと中継の流れを、別々の git worktree（書き込む場所を分けた作業用の複製）で並列に進め、タスクごとに、実装した Claude とは別の Claude が独立にレビューしました。判断・指摘・修正の記録は台帳に残してあります（台帳そのものはこのリポジトリには入れていません。ここに書く数字は、2026-11-05 09:51（日本時間）時点の台帳から数えたものです）。

- 実装のタスク：15（データ作り、計算エンジン、施設の表、境界の図形、中継、AIの道具、画面の骨組みと地図、町の詳細、前提と割り振りの画面、AIの画面など）
- 各タスクの独立レビュー：15回。初回で承認されたのは7タスク、残り8タスクは指摘を受けて1回ずつ直し、直した後にもう一度レビューして承認されました（修正ラウンド8、再レビュー8回）
- 指摘の内訳：致命的 0件、重要 17件（例：中継が、画面から来た項目の一部をそのまま通していた／回数の上限が同時アクセスで外れた／ファイルの読み込みが止まるとAIの画面が固まった／失敗できないテスト。詳しくは [docs/dev-log.md](docs/dev-log.md)）
- レビューは、変異テスト（コードをわざと壊して、テストが失敗するかを調べる）でも確かめました

**製品の中で**：「AIに質問」は、Anthropic の API（モデル `claude-sonnet-5-5`）を、小さな Cloudflare Worker 経由で呼びます。API キーは Worker にだけ置き、画面側（ブラウザ）には出しません。

- Claude は、次の8つの計算の道具を呼んで答えます。道具の名前・説明・入力の形は、Worker の側で決めたものだけが使われ、画面から送られた値は使いません。
  1. `find_area`：地域の名前からコードを探す
  2. `get_series`：地域の人口の推移（65歳以上の人数と割合も）
  3. `compare_sources`：公式の推計とこのアプリの試算を比べる
  4. `run_projection`：前提を変えて計算し直す
  5. `facility_check`：町の人口を施設の目安に当てはめる
  6. `run_allocation`：人口の割り振りを計算する
  7. `find_similar_now`：2100年の人口が、いまの人口と近い町を探す
  8. `count_areas`：条件に合う地域の数を数える
- 道具は、ブラウザの中で動く同じ計算エンジンを呼びます。Claude は結果を日本語で説明します。
- **答えの中の数字は、道具の結果で確かめてから出します。** 答えの数字が道具の結果の中に見つからないと、道具の結果にある数字だけで言い直すよう、1回だけ頼みます。それでも確かめられない数字が残ると、画面に「次の数字は、計算の結果で確かめられませんでした」と警告を出します。確かめの限界：0〜10の整数と、年（1900〜2100）は検査しません。答えの側で自分で計算した合計や比（たとえば「約28%」）は、道具の結果に無いので警告されます。
- 人が確かめる手段として、答えの下に「使った道具と数字」を開けます。割り振りの質問では、地図も同じ状態に動かせます。
- モデルの出力は、HTML として解釈せず、文字としてだけ表示します。
- AIには、勧めない・予測と書かない・「残せない」と書かない、といった決まりを、Worker の側の指示で渡しています。

## Claude が作った部分と、人が決めた部分

- **Claude が作った**：このリポジトリのソースコード、テスト、ドキュメントのすべて。Claude Code が書きました。実装を担当したサブエージェント（Claude Code が起動する子のセッション）は Claude Sonnet 5.5、画面の見た目を決めて実装したタスク（地図、色、書体、配置）は Claude Fable 5.1 が担当しました。全体を通したレビューにも Claude Fable 5.1 を使う予定です（このコミットの時点では未実施）。各コミットの末尾の `Co-Authored-By` が、そのコミットを作ったモデルを示します（2026-11-05 09:44 のコミット b2c3dfa までの42件のうち、Claude Sonnet 5.5 が39件、Claude Fable 5.1 が3件）。git の作者の欄は、作業をした環境の git の設定による名前になっていて、Claude であることを示すのは `Co-Authored-By` です。
- **人が決めた**：アイデアと方向（どんな問いに答える地図にするか）、機能の要件、画面の見た目の方向の承認（方向を決める段階で、見本を見て承認）、アカウントと権利に関する判断、公開すること。
- AI が生成した画像や音声は、使っていません（アイコンは、コードで書いた SVG の図形で、四角と丸だけです）。書体は、環境に入っているものだけで、Webフォントは読み込みません。
- OSS の依存関係（宣言されたライセンスは、各パッケージの `package.json` による）：D3 7.9.2（ISC）、topojson-client 3.1.0（ISC）。開発用に Vite 8.3.5（MIT）、TypeScript 7.0.2（Apache-2.0）、Vitest 5.1.0（MIT）、jsdom 30.1.3（MIT）、mapshaper 0.7.101（MPL-2.0。境界の簡略化に使用）、Wrangler 4.157.0（MIT OR Apache-2.0）、`@cloudflare/workers-types`・`@types/*`。ほかに、取り込んだ第三者のコードはありません。データを処理する Python は標準ライブラリだけです。
- 既存の素材：なし。このリポジトリは、ハッカソンの開始後に作りました。

## 動かす・試す・作る

必要なもの：Node.js と npm（開発は Node 26 で行いました）。データを作り直す場合は Python 3（標準ライブラリだけ。開発は 3.14）。

```sh
npm ci              # 依存関係を入れる
npm run dev         # 開発用サーバー（http://localhost:5173）
npm test            # テスト（Vitest）
npm run typecheck   # 型の検査（画面側と Worker 側）
npm run build       # 公開用のファイルを dist/ に作る
npm run test:py     # データ作りのテスト（先に python3 -m pipeline.fetch_sources が必要）
```

2026-11-05 時点の `build` ブランチ（コミット b2c3dfa）で、`npm test` は36ファイル784件がすべて通り、`npm run typecheck` と `npm run build` も成功します。`npm run test:py` は84件が通ります。

データの作り直し（`public/data` には作った結果を入れてあるので、普段は要りません）：

```sh
python3 -m pipeline.fetch_sources     # 社人研の Excel を data/raw に取得し、SHA256 を照合
python3 -m pipeline.build_areas       # 地域ごとの人口と前提の JSON（public/data/areas、groups.json、index.json）
python3 -m pipeline.build_facilities  # 施設の人口の目安（public/data/facilities.json）
bash pipeline/build_geometry.sh       # 境界の TopoJSON（public/data/geo）。国土数値情報の zip を取得して簡略化
python3 -m pipeline.check_codes       # 社人研の地域と境界のコードの突き合わせ
```

AI の中継（Worker）：作りと設定は [worker/README.md](worker/README.md)、画面から Worker への接続は [docs/ai-endpoint.md](docs/ai-endpoint.md)。Worker の公開には、Anthropic の API キーと、利用上限の設定、KV の作成が要り、これらは作者が行います（キーはコードにも設定ファイルにも書きません）。この版には公開した Worker はありません。

| `src/engine` | 計算エンジン（人口の計算、前提、施設の判定、割り振り）。画面にも AI にも依存しない |
| `src/data` | データの読み込みと、全地域を計算して覚えておく仕組み |
| `src/map` | 地図の描画（日本、県、色、凡例） |
| `src/ui` | 画面（骨組み、町の詳細、前提、割り振り、AIの画面）と、その設計 `DESIGN.md` |
| `src/ai` | AI の道具、答えの数字の検査、Worker へのやり取り、保存済みの答え |
| `worker` | Claude の API を中継する Cloudflare Worker |
| `pipeline` | 社人研・国土数値情報・施設の表から `public/data` を作る Python |
| `public/data` | 作った地域データ、境界、施設の目安 |
| `test` | テストで使う補助とデータ |
| `docs` | 出典、設計、開発の記録 |

## 限界と未完了

- 公開ページは未公開です。AI の自由入力の中継（Worker）も未公開です。そのため、公開前は自由入力は使えません。
- AI の「保存済みの答え」は未作成です（上記）。
- 国土数値情報の境界に付ける「測量法に基づく国土地理院長承認」の表示が、加工データに必要かは未確認です（[docs/sources.md](docs/sources.md) の未解決の点）。社人研のページの利用条件の原文も、まとめた時に読み直せていません。
