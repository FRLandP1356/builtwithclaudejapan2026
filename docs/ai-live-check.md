# 公開済み Worker の実機確認（scripts/ai_live_check.ts）

公開済みの Worker（`https://town-2100-api.your-account.workers.dev/api/chat`）を、画面と同じ `ask()`（`src/ai/client.ts`）で呼び、本物のモデルが道具・長い会話・キャッシュ・トークン数で期待どおりに動くかを確かめる道具です。保存済みの答え（`public/data/cached_answers.json`）の作成も兼ねます。秘密は読まず、書かず、表示しません（API キーは Worker の中にだけあります）。

## 実行方法

```sh
node scripts/ai_live_check.ts --log <ログの保存先.json>          # 既定は 1,2,3,3b,7 の全部
node scripts/ai_live_check.ts --phases 7 --log <保存先.json>      # 一部だけ
node scripts/ai_live_check.ts --phases 1 --only q5                # 保存用の質問のうち q5 だけ聞き直す（最大 3 回）
node scripts/ai_live_check.ts --dry-run                           # 通信せず、道具とデータの読み込みだけ確かめる
```

Node 26 が型を外して実行し、`src/` の拡張子なしの import は、スクリプト自身が起動する Vite（ミドルウェアモード）が解決します。`vite-node` は入っていません。各回の質問の間は 4 秒以上あけ、429 と 503 は 30 秒待って最大 3 回やり直します。見積もりが 15 ドルを超える、503 が 2 回続く、200 以外が 6 回続く、330 回を超える、のどれかで自分で止まります。

## 段階

| 段階 | 内容 |
|---|---|
| 1 | 保存用の 5 つの質問を、それぞれ新しい会話で聞く。答えを `cached_answers.json` に書く（status は必ず `pending`） |
| 2 | 9 つの道具ごとに 1 つ質問を作り、本物のモデルが道具を呼ぶまで聞く（`run_allocation` は、減る地域を聞く質問をもう 1 つ持つ） |
| 3 / 3b | 12 問以上の長い会話を 2 本。履歴を毎回渡し、古いやり取りが捨てられる（trim）ところまで行く。3b は「差・割合・倍率」を聞き、モデルが考えてから道具を呼ぶ場面を増やす |
| 7 | 一言の質問と、約 20,000 文字（本文 49.5KB）の質問で、入力トークン数を測る |
| 4・5 | キャッシュの読み出しと `stop_reason` の集計（ログから計算） |

全部の上流の応答について、`stop_reason`・`usage`・`input_transformations`・`model`・ブロックの種類と長さ・HTTP の状態・時間を記録します（答えの本文は 200 文字まで）。

## 結果（2026-11-06、2 回実行。合計 161 回、見積もり約 1.18 ドル）

| 項目 | 結果 |
|---|---|
| 呼び出し | 1 回目 65 回（0.44 ドル）、2 回目 96 回（0.74 ドル）。すべて HTTP 200。429・503・400・502 は 0 件 |
| 道具の定義 | 8 つすべて受け付けられた（400 なし）。8 つとも本物のモデルが呼び、結果にエラーなし |
| 道具の往復 | `tool_use` → `tool_result` → 答え が通った（1 つの質問は 1〜4 回の呼び出し） |
| 長い会話 | 12 問を 2 本。どちらも 4 回の質問で古いやり取りを捨てた。400 は 0 件 |
| `input_transformations` | 捨てる前は、思考ブロックがあっても全部 `[]`（30 回）。捨てたあとは、思考ブロックが残る呼び出し 20 回のすべてで `thinking_dropped`（理由 `prefix_binding_mismatch`）。ほかの種類は 0 件 |
| キャッシュ | 全 161 回のうち、最初の 1 回（書き込み 5,941）を除く 160 回が、前の呼び出しから 5 分以内に `cache_read_input_tokens` 5,941 を読んだ（100%。読み出しの大きさは毎回同じ） |
| `stop_reason` | `tool_use` と `end_turn` だけ。`max_tokens` と `refusal` は 0 件（出力は最大 578 トークン。2 回目の通しだけなら 548） |
| トークン数 | 一言の質問は入力合計 6,023（道具とシステムの前置き 5,941 ＋ 82）。20,000 文字の質問は 23,302。質問分は 17,279 で、1 文字 0.86、日本語の文字だけで数えて 1.19、本文の 1 バイトあたり 0.35（README の上限の 1 トークン/バイトの 43%） |
| 応答時間 | 1 回の呼び出しは中央値 2.3 秒、最大 5.9 秒（1 回目の通しの最大。2 回目の通しだけなら 5.2 秒。KV の読み取りを含む） |

この結果は、道具が 8 つだった時の通しです。そのあとで 9 つ目の `get_age_groups` を足し、`run_allocation` の結果に減る地域の一覧（`largestDecreases`・`decreaseSummary`）を足しました。

## 試していないこと

- 9 つ目の道具 `get_age_groups` と、`run_allocation` の減る地域の一覧。単体試験で確かめてあり、本物のモデルが呼ぶか、答えの数字が確認を通るかは、実機では試していません（段階 2 に質問を足してあります）。
- 回答を断る（`refusal`）経路。単体試験で確かめてあり、実機では試していません（段階 6 は省きました）。
- 1 日の上限（429）。再デプロイが要るため省きました（単体試験あり）。
- 429・503 のやり直し。今回は一度も起きなかったので、実機では動いていません（手元の偽 Worker では確かめました）。
- 5 分を超えてあいた後のキャッシュ。
- 並行する多数の利用者、複数の拠点での数え方。
- Workers Logs に実際に記録された行を開いて、接続元の IP や API キーが入っていないことを見る確認（`worker/README.md` の手順 9 の最後）。
- 公開した Worker の Cloudflare のプランが無料か有料か。確認の呼び出しは 235 回でしたが、プランは確かめられていません。

結果の元データは実行時に指定したログ（1 呼び出し 1 項目）です。

## 追記（同じ日の少しあと、73 回・約 0.60 ドル）

- 保存用の 2 つ目の質問を、道具で答えられる「田辺市の2100年の人口は何人くらいで、65歳以上は何割ですか？」に替えた（子どもの数を返す道具は無いため、前の質問は「分かりません」と答えていた）。
- 試算の最初の年は 2055 年（公式は 2050 年まで、5 年刻み）。道具の結果の文・道具の説明・システムの指示から「2060 年から」を直した。
- 数字の確認は、同じ会話の前の回の道具の結果（`tool_result`）も使う。前の回の答えの文や質問の文だけにある数字は、これまでどおり確認できない扱い。2 本の長い会話（24 問）で、確認できない数字の警告は 4 件から 0 件になり、呼び出しは 59 回から 57 回になった。
- 保存済みの答えを作り直した。q1〜q4 は、数字がすべて道具の結果にあることを確かめた（読んで正しさを確かめたのではない）。q2 の「社人研の公式推計では、2050年の人口は42,311人」は、社人研の表では 42,309 人で、42,311 はこのアプリの計算値（[dev-log.md](dev-log.md) の 6.4）。q2 と q5 は、システムの指示にある言い回しをモデルがそのまま使うため、「予測ではなく」という否定の形で「予測」の語を含む。q3 は、道具の結果が増える地域の上位しか挙げないので、減る地域を答えられない。5 件とも `pending`。
- **q5 は、最初は、公開済みの Worker が古い道具の説明とシステムの指示を送っていたため、4 回とも「2060 年から」と答えた。Worker の再デプロイのあとで聞き直し（1 回、約 0.02 ドル）、「2055 年から 2100 年まで」と答えた（コミット a15e934）。** `cached_answers.json` の q5 の note の WRONG は外れた。
