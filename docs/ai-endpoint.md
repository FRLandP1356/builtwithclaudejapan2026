# 「AIに質問」の問い合わせ先

画面は質問を、ビルドのときに環境変数 `VITE_CHAT_ENDPOINT` で決めた Worker の URL に送ります（例: `VITE_CHAT_ENDPOINT=https://example.workers.dev/api/chat npm run build`。未設定なら同じ出どころの `/api/chat`）。ビルドで文字列に埋め込まれるので、変えたら作り直します。
Worker は、公開ページの出どころ（`https://…`、末尾の `/` なし）を `ALLOWED_ORIGINS` に入れておく必要があります。入っていないと Worker は 403 を返しますが、その応答には CORS のヘッダーが付かないため、ブラウザは 403 を画面に渡さず、通信の失敗として扱います。画面から見ると Worker に届かなかった場合と区別できず、429 と同じ扱いになります。つまり、同じ質問の確認済みの保存済みの答えがあればそれを出し、無ければ「いまはAIに接続できません。時間をおいて、もう一度お試しください。」と出ます（「保存済みの質問」のボタンは、確認済みの答えがある質問にだけ出ます。この版にはまだ1件もありません）。原因の確認は、ブラウザの開発者ツール（ネットワークとコンソール）で行います。
接続先に Worker が無いとき（たとえば `VITE_CHAT_ENDPOINT` を設定せずに、Worker のない静的なホストへ置くと、`/api/chat` が 404・405、またはページの HTML のように Worker の答えではない本文を返します）、画面は「このバージョンでは、AIへの質問は使えません（AIの接続先がまだ用意されていません）。地図、数値、前提の調整、人口の割り振りはそのまま使えます。」と出します。この文は、その接続先から一度も本物の答えが返っていないページにだけ出ます。一度でも答えが返ったあとの失敗は、404・405 も含めて、上の「時間をおいて、もう一度」の扱いです。そのため Worker は、404・405 を、パスやメソッドの間違いにだけ使います（一時的な不調には使いません）。ファイルとして開いたページ（`file:`）の標準の接続先だけは、通信の失敗もこの文になります。
1 日の回数の上限（既定は 1 つの IP あたり 60 回、全体で 400 回。上流への呼び出しの回数で、1 つの質問は最大 9 回使います）と、60 秒に 20 回の連続の制限があります。超えると 429 で、画面は同じ扱いにします。お金の確実な上限は、Anthropic のワークスペースの利用上限だけです。公開前の手順は `worker/README.md` の「公開前のチェックリスト」です。
