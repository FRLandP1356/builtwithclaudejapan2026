## 1. 詰まった場面：公式の2050年を再現したら、全国で約10%高く出た

最初のコミット（06:19、f241901）より前に、公開されている前提だけで社人研の2050年の結果を再現できるかを、使い捨ての Python の試作（リポジトリの外）で試した。時刻はリポジトリに記録が無い。試作の作業ファイルの更新日時（作者の機械の一時フォルダ。読者は確かめられない）は、05:00〜05:05ごろだった。

- 最初の計算は、全国の2050年が公式より約10%高かった。
- 年齢別に見ると、ずれていたのは0〜4歳だけで、公式の1.43倍だった。ほかの年齢は合っていた。
- 0〜4歳は「子ども女性比 × 次の期の女性の数」で出す。子ども女性比の分母を、一般的な「15〜49歳の女性」にしていたのが原因だった。社人研が公表している子ども女性比と、公表している人口から逆算して、分母は**20〜44歳の女性**と確定した。
- 直すと、前提が公表されている1,871地域で、2050年の人口のずれの中央値が0.005%になった。公表されている前提が、公式の結果の計算に使われた値そのものだった、と言える。

TypeScript のエンジン（Task 5。コミット 8da53e7、06:49）でも同じ結果を確かめた。前提が公表されている1,871地域の合計で、2025年の0〜4歳は、エンジン 3,952,306人に対して公式 3,952,307人（-0.00003%。公式の値はテストの中に、出どころを添えて固定してある）。2050年は、同じ1,871地域のずれが、中央値 0.0053%、最大 1.39%。全国の合計は、前提が公表されていない13村（公式の年齢別人口をそのまま使う）を足した1,884地域で、エンジン 104,686,401人に対して公式 104,686,386人。この再現は、テストとして常に走る（しきい値は README にある）。

## 4. 作業の進め方

- **並列のストリーム**：データ、計算エンジン、境界、中継、AI、画面を、別々の git worktree（書き込む場所を分けた作業用の複製）で並列に進めた。担当する場所が重ならないようにし、`git merge --no-ff` で `build` ブランチに入れた。依存関係は最初の Task 1 で全部入れ、並列の作業で `package.json` が衝突しないようにした。修正の波も、4つの worktree で同じ形を取った。
- **台帳と裁定**：作業の途中で見つかった食い違い（型を置く場所、道具の数、計算の入力の範囲など）は、その場で「裁定」として台帳に書いた（番号は 1〜37 の37件。うち 8 番は 3 番を指すだけ）。最初のタスクを始める前の点検で、計画のタスク同士の食い違いを14件見つけて、先に裁定した。
- **番号の読み方**：コードのコメントにある「Ruling N」「Task N」は、台帳の裁定とタスクの番号を指す。台帳はこのリポジトリには入れていないので、コメントだけでは、番号の中身は分からない。
- **独立レビューと変異テスト**：各タスクで、実装とは別のレビューを行い、指摘は修正ラウンドで直して再レビューした（タスクでは修正ラウンド10回、修正の波では7回）。テストを先に書き、失敗するのを確かめてから実装する形を取った。
- **見た目の方向は、段階を踏んで決めた**：画面の見た目（色、書体、配置）は Task 8 で1回だけ、Claude Fable 5.1 が決めて実装した（3コミット）。進行役が 390px と 1512px で実機を確かめ、スクリーンショットを作者に見せて、方向の承認を得てから町の詳細（Task 9）などに進む、と決めてあり（台帳の裁定 23）、承認は Task 9・10 の着手より前に記録されている。Task 9 以降は、決めた色と部品を使う決まり（裁定 23）で進めた。
- **公開は承認制**：公開、Worker の公開（`wrangler deploy`）、提出は、承認を得てから行うと決め、台帳に「公開の関門」として残した。Worker の公開は、サーバー側の道具の定義への切り替え、別の会社の AI によるレビュー、承認の3つが揃うまで行わず、Anthropic のワークスペースの利用上限も先に設定する、と決めた。2つ目は実施できていない（次の5）。代わりに行った Claude のレビューは補いで、他社のレビューではない。公開するかどうかは、この点も含めて作者が判断する。公開も、Worker の公開も、まだ行っていない。
