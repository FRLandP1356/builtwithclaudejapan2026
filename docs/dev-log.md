## 1. 詰まった場面：公式の2050年を再現したら、全国で約10%高く出た

04:00〜05:00ごろ、公開されている前提だけで社人研の2050年の結果を再現できるかを、使い捨ての Python の試作（リポジトリの外）で試した。

- 最初の計算は、全国の2050年が公式より約10%高かった。
- 年齢別に見ると、ずれていたのは0〜4歳だけで、公式の1.43倍だった。ほかの年齢は合っていた。
- 0〜4歳は「子ども女性比 × 次の期の女性の数」で出す。子ども女性比の分母を、一般的な「15〜49歳の女性」にしていたのが原因だった。社人研が公表している子ども女性比と、公表している人口から逆算して、分母は**20〜44歳の女性**と確定した。
- 直すと、前提が公表されている1,871地域で、2050年の人口のずれの中央値が0.005%になった。公表されている前提が、公式の結果の計算に使われた値そのものだった、と言える。

TypeScript のエンジン（Task 5。コミット 8da53e7、06:49）でも同じ結果を確かめた。2025年の0〜4歳は、エンジン 3,952,306人に対して公式 3,952,307人（-0.00003%）。2050年は、ずれの中央値 0.0053%、最大 1.39%、全国 104,686,401人（公式 104,686,386人）。この再現は、テストとして常に走る（しきい値は README にある）。

## 2. 2つ目の訂正：出生率の倍率を、1期早く掛けていた

- 画面で動かす「子どもの生まれやすさ」の倍率は、2050年より後の期にだけ掛けるはずだった。試作は、2045→2050年の期から掛けていた（1期早い）。
- そのままでは、2050年の公式の数字も倍率で動いてしまう。また2100年の全国の合計が、約2%ずれた。試作を再実行して確かめた値は、倍率1.2で 7,245万人（訂正後 7,093万人）、0.8で 5,510万人（訂正後 5,634万人）。
- 見つかった経緯は、試作とは別に出した数字とテストを突き合わせる段階だった、という進行役の説明による（台帳に残っているのは、訂正の内容と訂正後の値）。台帳では、Task 5 の完了報告の直前に「Ruling 19」として記録し、設計書と計画の表の数字を直した。エンジンは「2050年を終点とする期より後だけに掛ける」形に決め、倍率を1.2にしても2050年が変わらないことをテストにした。

## 3. レビューで見つかったこと（台帳から）

各タスクは、実装した Claude とは別の Claude が独立にレビューした。重大な指摘はなく、重要な指摘が17件あった。例：

- **中継が、画面から来た項目の一部を通していた**（Task 12、台帳 06:52）。キャッシュの有効期間の指定、画像や文書の URL を含む道具の結果、偽の道具名を含む過去のやり取りが、そのまま上流に届いた。ブロックを、決まった項目から作り直す形に直した。別の自動のセキュリティ点検（台帳 06:40）は、道具の定義も画面から来るのは危ないと指摘し、道具の名前・説明・入力の形を、サーバー側の1つのファイルに集めた（Task 13a）。
- **回数の上限が、同時アクセスで外れた**（Task 12）。1つのIPで1日3回、全体で5回の上限に、50件を同時に送ると、50件とも通った。保存と読み出しが別の操作で、同時に読んだ要求が互いの書き込みを上書きするため（KV に「足し算を1回で行う」命令が無い）。時間が足りず別の仕組み（Durable Object）には替えなかった。代わりに、この上限は「できるだけ」の目安であり、お金を止める本当の上限は Anthropic のワークスペースの利用上限だと決めて、書き込みの順を直し、README と公開前のチェックリストにそう書いた。IP は、鍵つきのハッシュ（HMAC）で保存し、IPv6 は /64 の範囲で1人と数えるようにした。
- **ファイルの読み込みが止まると、AIの画面が固まった**（Task 13b-2、台帳 10:35）。保存済みの答えのファイルが返ってこないと、状態の表示も「やめる」も出ず、以降の質問も止まった。待つ前に表示を出し、1.5秒で待つのをやめて実際の呼び出しに進むようにした。
- **会話が長くなると、毎回断られる要求を送っていた**（Task 13b-1）。10回ほど質問すると、中継が決めた大きさの上限を超え、「時間をおいて、もう一度」という誤った案内が出るだけだった。送る前に毎回大きさを測り、古いやり取りをまとまりごとに捨てるようにした。
- **失敗できないテスト**（Task 9、10、13b-2）。コードをわざと壊しても通るテストを、変異テストで見つけた。たとえば Task 9 では27通りの壊し方のうち14通りが通ってしまい、テストを足して、再レビューで35通りの壊し方がすべて検出されることを確かめた。Task 10 の再レビューは22通りがすべて検出された。Task 13b-2 は42通りのうち37通りが検出され、残りに対応するテストの不足は、指摘として修正ラウンドに含めた。
- **画面の重なり**（Task 8）。1512px 幅で、年のスライダーの目盛りの文字が「試算」の注記と重なっていた。進行役が実機で見つけ、修正ラウンドで直し、360〜1920pxで重ならないことを確かめた。

## 4. 作業の進め方

- **並列のストリーム**：データ、計算エンジン、境界、中継、AI、画面を、別々の git worktree（書き込む場所を分けた作業用の複製）で並列に進めた。担当する場所が重ならないようにし、`git merge --no-ff` で `build` ブランチに入れた。依存関係は最初の Task 1 で全部入れ、並列の作業で `package.json` が衝突しないようにした。
- **台帳と裁定**：作業の途中で見つかった食い違い（型を置く場所、道具の数、計算の入力の範囲など）は、その場で「裁定」として台帳に書いた（30件）。作業を始める前の点検（06:35）で、計画のタスク同士の食い違いを14件見つけて、先に裁定した。
- **独立レビューと変異テスト**：各タスクで、実装とは別のレビューを行い、指摘は修正ラウンドで直して再レビューした（修正ラウンド8回）。テストを先に書き、失敗するのを確かめてから実装する形を取った。
- **見た目の方向は、段階を踏んで決めた**：画面の見た目（色、書体、配置）は Task 8 で1回だけ、Claude Fable 5.1 が決めて実装した。進行役が 390px と 1512px で実機を確かめ、スクリーンショットを作者に見せて、方向の承認を得てから（台帳 08:11）、町の詳細（Task 9）などを進めた。
- **公開は承認制**：公開、Worker の公開（`wrangler deploy`）、提出は、承認を得てから行うと決め、台帳に「公開の関門」として残した（Worker の公開は、サーバー側の道具の定義への切り替え、別の会社の AI によるレビュー、承認の3つが揃うまで行わず、Anthropic のワークスペースの利用上限も先に設定する、と決めた。2つ目のレビューは次の5のとおり実施できず、Claude の全体レビューで補い、作者に伝える、と台帳に書いた）。

## 5. うまくいかなかったこと

- **別の会社の AI によるレビューができなかった**。Worker のコード（API キーとお金に関わる）は、本来は、別の会社の AI に独立にレビューさせる方針だった。しかし、OpenAI の Codex は2つのアカウントとも利用枠の上限に達し（2026-11-11 02:48 まで。台帳 07:17〜07:55）、Google の Antigravity（Gemini）をコマンドラインから無人で動かす手段は、実行の許可の仕組みに止められた（台帳 08:10）。そのため、Worker の安全性の確認は、各タスクの Claude のレビュー、自動のセキュリティ点検、Claude の全体レビューで行った。**別の会社の AI によるレビューは、実施できていない。** 全体を通した Claude Fable 5.1 のレビュー（Worker の安全性を明示した依頼）は、このコミットの時点では未実施。
- **回数の上限を確実な仕組みにできなかった**（上の3）。お金の上限は、Anthropic のワークスペースの利用上限に頼る。
- **国立環境研究所のデータを使えなかった**。元の Excel の再配布の可否が確認できず、数値をリポジトリに入れなかった。参考の線は、この版に無い。
- **社人研のページの利用条件を、読み直せなかった**。出典をまとめた時（このコミットの作業）に、社人研のページは自動のアクセスに 403 を返した。
- **AIの保存済みの答えを、まだ作れていない**。実際の Claude の答えを人が確認して保存する作業が、Worker を動かせる状態になってからになる。

## 6. 感想の材料（事実）

- 公的な統計の仕様は、公表された前提と結果を突き合わせて読み取る必要があった。ずれが出ても、年齢別に分けて見ると原因（0〜4歳の分母）が絞れた。
- 「人口の移動が止まる」前提は、全国の人口を減らす一方で、人口が減っている小さな町では増やす（田辺市の2100年は 11,880人から 13,690人）。Task 11 の報告で、画面と AI の説明に「移動が止まる＝人口が減る」と書かないよう、申し送りをした。
- 数字を出す部分（計算、AIの道具、答えの数字の検査）には、テストを先に書き、変異テストで確かめた。それでも、レビューのたびに、失敗できないテストや、入力の範囲の抜けが見つかった。
- 日本語の公式資料（社人研の Excel、国土交通省の PDF と規約のページ）は、探せば一次資料に当たれたが、図の中の数値は文字情報が崩れていて、画像に描画して目で読み、文字情報と突き合わせる必要があった（施設の表）。
